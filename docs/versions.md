# 版本适配与实机验收

`versions.js` 从 `bot.version`、`supportFeature`、实际注册表和 `bot.game` 生成事实。内容是否存在只查物品、方块、实体注册表，不靠版本号猜；因此模组补充的同名内容也能识别。`release` 按数字三元组比较，`26.1` 是 `[26, 1, 0]`，不会当作 `1.26.1`。

## 机制差异

| 版本范围 | 副手与攻击 | 物品名称、格式 | 原版主世界高度与知识 |
|---|---|---|---|
| 1.8.8~1.8.9 | 无副手，无攻击冷却，连点攻击 | `log`、`planks`、`wool`、`fireworks` 等旧名，NBT | 0~255，旧矿石分布，普通怪物刷怪亮度 ≤7 |
| 1.9~1.12.2 | 有副手和攻击冷却 | 旧名，NBT | 0~255，旧矿石分布，普通怪物刷怪亮度 ≤7 |
| 1.13~1.17.1 | 有副手和攻击冷却 | 扁平化现代名，NBT | 0~255，旧矿石分布，普通怪物刷怪亮度 ≤7；铜自 1.17 有 |
| 1.18~1.20.4 | 同上 | 现代名，NBT | -64~319，新矿石分布，普通怪物需要方块光照 0 |
| 1.20.5~1.21.x | 同上 | 物品组件补丁 | -64~319，沿用新版分布 |
| 26.1 系列 | 同上 | 物品组件补丁 | 以服务器维度信息为准 |

这张表描述原版默认机制。实际坐标界限优先取 `game.minY` 和 `game.height`，缺失时才按 `tallWorld` 回退；下界、末地和自定义维度不能直接套主世界高度。`setWorldBounds` 只接受 `-2032 ≤ minY < maxY ≤ 2031` 的整数，默认仍是 -64~319，不改变横向坐标、AI 动作和参数校验边界。

内容摘要覆盖下界合金、铜、深板岩、紫水晶、下界更新方块、幻翼、重锤、试炼刷怪笼、收纳袋、樱花、红树、嘎枝（嘎吱）、快乐恶魂、骆驼、弩、三叉戟、盾牌、鞘翅和蜂巢；只列缺失项，总长不超过 400 字。注册表存在收纳袋不保证该服已开启对应实验功能。

## 旧名别名

只在 `!theFlattening` 时给 `itemsByName`、`blocksByName` 分别添加缺失键，引用旧条目，不覆盖已有键、不改 ID、配方或元数据；返回数量按实际新增的字典键计算。重复安装返回 0。

| oak_planks | planks |
| oak_sapling | sapling |
| oak_leaves | leaves |
| white_wool | wool |
| grass_block | grass |
| firework_rocket | fireworks |
| sugar_cane | reeds |
| oak_slab | wooden_slab |
| oak_door | wooden_door |

木、金、石、铁、钻石的 `shovel/pickaxe/axe/sword/hoe` 工具在 1.8.8 和 1.12.2 已使用 `wooden_*`、`golden_*`、`stone_*`、`iron_*`、`diamond_*`，表中保留相同名字的映射，实际不会新增或覆盖它们。本地 `minecraft-data 3.119` 的两个版本都已逐条核对，测试也会验证每个旧名存在、别名对象一致和幂等性，没有未经注册表核验的旧名。

旧版同一 ID 的木头、羊毛和床继续用元数据区分。`oak_log` 和 `red_bed` 分别指向 `log` 和 `bed` 的整个旧条目。挖掘和查询不会按橡木或红床变体筛选，背包和工作流计数继续使用 `log` 等旧条目名。矩阵验证基础挖掘与工作台合成。`get`、`plan`、带元数据的配方及依赖现代物品名计数的工作流不在旧版兼容范围。

## 知识库与来源边界

`useVersion(facts)` 与 `useMods` 一样设置当前上下文；`relevantTips` 在排序之前过滤 `since` 和 `until`，两端都包含。没有设置版本时不做版本过滤，调用 `useVersion(null)` 可恢复。模组知识也经过同样的区间过滤。

1.17 及更早的矿石建议按本次任务提供的 Minecraft Wiki 历史分布整理：钻石 Y 5~12（11 附近最多）、铁 0~63、金 0~31、红石 0~15、青金石 0~30（13~16 最多）、煤 0~127；1.17 的铜 0~96。恶地额外金矿 Y 32~79 另设自 1.10 开始的条目。下界合金和远古残骸从 1.16 起提供，铜从 1.17 起提供；没有把旧分布带到 1.18 之后。

这些数字为默认世界生成下的生存建议区间。服务器的模组和数据包可以改变生成规则。

## 火箭格式与飞行白名单

`flightVerified(version)` 只读取常量集合，当前为 `26.1`、`26.1.1`、`26.1.2`。它表达项目的人工实测准入，不能从协议支持、拥有鞘翅、火箭格式可解析或单元测试通过推导出来，也不表示本次重新验证了这三个版本。

- 组件格式沿用已有一致性检查：`componentMap`、原始组件数组、移除组件列表必须齐全；拒绝被移除、重复、命名冲突、原始值与 Map 不一致的烟花组件。原版默认的空补丁表示 Flight 1、无爆炸；显式覆盖也必须是 `flightDuration: 1` 和空 `explosions`。
- NBT 格式只认 `nbt.value.Fireworks.value.Flight.value === 1`，同时验证 compound/byte 结构；`Explosions` 缺失或是空的 compound/end 列表才通过。`nbt: null` 是默认 Flight 0，拒绝使用。1.13 前物品叫 `fireworks`，之后叫 `firework_rocket`。
- 两种格式都要求整数数量 1~64、名称与格式对应，并且版本在白名单。旧版 NBT 正例仅在测试内替换版本门来验证，生产不会因此开放旧版飞行。

增加白名单的流程：先运行目标版本的完整矩阵并加 `--flight`，保留 JSON、TXT、机器人状态日志和实际坐标证据；核验起飞、火箭消耗、降落、到达和途中停止。对未在白名单的版本，矩阵应该观察到步行，它只能采集现有准入行为，不能证明飞行成功。需要真正验证候选飞行时，由人工在隔离工作副本临时加入候选版本后重复实测，并确认协议动作和安全边界；通过审查后才修改仓库集合、补回归测试。矩阵脚本自身永不写白名单。

## 串行版本矩阵

```sh
npm run lab:versions -- --out /tmp/mc-bot-versions \
  1.8.8 1.12.2 1.16.5 1.17.1 1.18.2 1.20.4 1.21.4 26.1
node scripts/lab/version-matrix.js --out /tmp/mc-bot-flight --flight 26.1
```

默认镜像 `itzg/minecraft-server:java25`，游戏端口 25590，RCON 25591，均只绑定 `127.0.0.1`。可用 `--image` 和 `--port` 指定。若镜像内 Java 与旧服务端不兼容，按版本分批选择适合的镜像。单服内存 1500M，启动最多等 6 分钟，一次只启动一个。

脚本复制仓库到系统临时目录，排除数据、日志、配置、环境文件、工作流、`.dual-dev` 和可执行扩展，仅给 `node_modules` 建符号链接。机器人自动检测版本，关闭 AI、自主模式、继承的外部控制台和 Agent API。RCON 指向实验服，容器名使用 `mc-bot-version-lab-<版本>-<随机后缀>`。

检查自动检测、版本事实日志、三个查询指令、原木别名挖掘、工作台合成、泥土挖掘、持剑守卫、`come`、`goto` 和途中 `stop`。场地为 x -12..44、z -12..12，y=99 铺地、y=100..107 清空。关闭观察账号的本地物理，传送到 (16,100,0)，1.14+ 额外预加载区块。四角加载后才建造，读回采样点确认地面和净空。把实验世界出生点移到场内，再启动机器人。`goto` 第一程到 x=30，第二程朝 x=-10，观察到实际移动后发 `stop` 并核对位移停止。

挖掘、合成和火箭数量通过 `bot inv` 回读，收齐回复后按注册表名计数，例如 1.13 前的 `log`。挖矿前由观察账号读回测试方块，并留出服务端同步时间。战斗先核验铁剑，再按注册表实体名召唤僵尸，以服务器指名击杀日志为证据，旧版则用目标消失或死亡配合本轮机器人获得的 Monster Hunter 记录。

`--flight` 对白名单版本加载 400 格外的自然地面、给鞘翅和 Flight 1 火箭，在 y=200 的临时高台站稳起飞，完整核验飞行、火箭消耗、降落与到达。测试账号处于创造模式，跟随观测坐标；被测机器人仍是生存模式，高处测试加抗性与饱和效果以避免摔落和饥饿干扰。非白名单版本留在 y=100 场地上，有鞘翅的版本同样发放鞘翅和火箭，发 `bot goto 400 100 0`，观察回复包含“步行”后立即 stop，只核验没有 `[flight] … CLIMB` 且火箭数量不变，不要求走到。记录实际路线与交通日志，环境不适合时如实 FAIL，不自动放开白名单。

每版输出 `<out>/<版本>.json` 和 `.txt`，包含逐项 PASS/FAIL、细节和机器人/服务器日志，最后写 `summary.json`。全通过退出 0，否则 1。失败或 Ctrl-C 后，脚本停止子进程、删除本轮测试容器及匿名世界卷、清理临时副本。容器删除失败会停止后续版本。遇到 SIGKILL、Docker 守护进程失联或主机断电，恢复后可按实验容器前缀检查残留。
