# 长期记忆与 Agent 执行闭环（v1 设计）

## 目标与范围

机器人在玩家任务或普通待机中，被动记住门户、遗迹/结构候选、设施、资源和危险点，并把相关历史交给现有 Agent。关闭自主行为不会关闭记忆；记住地点不授权走过去、穿门、挖掘或消耗资源。本轮先提交实现与验证的 PR，不部署生产。

未设置世界 ID 时现有 `note`、`mark/places`、箱子缓存、任务经验继续走旧路径；设置世界 ID 后，地点、箱子、经验分别使用该作用域的独立文件，旧文件保留但不隐式导入；新系统提供有来源的世界事实与行动结果层，不让模型把自己的回答存成已证实事实。旧文件不原地迁移、不默默绑定到新世界。

## 身份、事实与置信度

- 作用域由规范服务器地址/端口和显式 `MC_MEMORY_WORLD` 组合成 opaque key。世界重置或代理切换后必须换 world ID；客户端不能可靠自动识别世界重置。未配置时新自动事实不持久化，旧功能照常。
- `dimension` 表示实际 level key，优先取协议 `worldState.name`，不能把自定义世界的相同 dimension type 合并。无法取得时使用规范化 `bot.game.dimension`，并记录回退边界。
- 门方块/矿石等来自已加载块数据，是 `observed`；这不等于玩家视线可见。结构特征组合固定为 `candidate`，玩家建筑也可能拥有这些特征。
- 玩家命名/纠正是 `reported`，保留操作者；人工确认连接只能成为 `user_confirmed`，不会伪装成服务端认证。
- 普通 chunk 没有自然结构名称标签。v1 不订阅需要额外权限的 debug 数据，不使用 `/locate`、服务端文件或未加载区块探测。模组世界只暴露 `modded_block` 时不猜具体结构名。

## 存储与维护

`long-memory.js` 工厂管理单世界 JSON 快照：`schemaVersion/worldKey/records/edges/tombstones/enabled`。记录包含 ID、类型、level、位置、来源、有限证据、首次/最后观察、状态、人工名称和 pin。原子临时文件加 rename；自动观察最多五秒合并写盘，人工管理立即写盘，退出显式 flush。

容量分开限制自动记录 256、人工/pin 64、连接 256；整个文件最多 256KiB。证据最多八条，历史有界。仅淘汰未 pin 自动记录，不挤掉人工地标。损坏、超限、未来 schema 或世界不匹配时降级只读，保留原文件，明确报告写入失败。

相邻门户按连通簇合并（包括乱序桥接），保留有界旧ID别名并规范化连接引用；多个独立人工记录冲突时不强并。结构按邻近区域聚合；TTL 只标“陈旧待核实”，未加载不能当作被拆。实际加载位置发现原特征消失才标失效。删除留下墓碑，避免下一轮扫描立刻重建；自动发现不得覆盖人工名字、pin、纠正或失效决定。

## 有预算的观察

`memory-observer.js` 只读取当前已加载的近处方块，分批扫描并处理有界更新队列。每次工作有块数和时间预算，无寻路、挖掘、开箱或网络订阅副作用。结构规则需要明确特征，输出候选和证据，不凭一个普通圆石/木板判村庄或遗迹。

v1 白名单：要塞（末地门框）、远古城市（强化深板岩+幽匿块）、试炼密室（试炼刷怪笼+宝库）、下界要塞（下界砖+下界砖栅栏）、堡垒遗迹（镶金黑石+磨制黑石砖）、末地城（紫珀块+末地石砖）、海底神殿（暗海晶石+海晶灯）。这些都仅为候选。设施为箱子、木桶、熔炉、工作台、附魔台、铁砧、酿造台、信标；资源为矿石与远古残骸；危险点先覆盖岩浆。

广域观察默认半径8、每秒最多256次块读取与5ms扫描预算；更新队列512、特征/门户缓存各2048。门户身体接触另走 move/physics/forcedMove 轻量路径，每事件最多8格且重复身体单元复用，避免漏掉两次广域扫描之间的快速末地传送。出口必须收到新位置且至少两次间隔500ms的位置样本稳定；从磁盘加载的门户锚点也纳入有界复核。

门户连接需要先观察到身体与活动门方块重叠，之后发生真实 level 切换或同 level 远距传送；出口位置稳定后，最多登记有方向的候选边；若看到对应门则关联门 ID，否则记录可能动态变化的抵达点候选（例如末地平台、床或出生点），不凭坐标固定未来回家出口。管理员传送不能从客户端彻底排除，所以不会自动确认边。初次登录、死亡、断线、已知测试/管理员传送抑制归因；下界 1:8 关系不是连接证据，末地回家出口也不自动生成反向边。

## Agent 闭环

1. 捕获 `{worldKey, level, epoch, position, inventory}`，按目标和当前 level 检索最多六条/1600字记忆；候选、陈旧、人工报告均明确标记。记忆只进入不可信 state，不提升为 system 指令。
2. 现有模型和任务清单给出下一步动作，原参数校验、预算、优先级、玩家抢占继续生效。
3. 共用程序以 `passed / failed / unknown` 三态判定 action 结果：明确失败不能因一条回复或空返回被记为成功；空间到达要核对目标、level 和实际位置；物品结果基于实际快照，不能仅凭模型 `done`。清空区域半径最多4格做完整已加载检查，更大的清空条件保持 unknown，留待后续有预算的区域核验器。
4. 行动后重新观察。epoch/level 变化即取消原维度任务和旧响应，不能在新维度提交旧结果；容器收尾绑定打开时的 level，不能污染新世界或关闭新窗口。
5. 当前条件满足不等于 Bot 造成；共享背包增量和原已存在方块尤其不能证明因果。提交成功经验前重新核验全部必要任务，缺证据记 `unverified`。只有持久化成功才能回复“记忆已写盘”。只把程序有证据的结果作为可复用成功经验；不具备验收依据的行动保留为未核验尝试，不升级成成功配方。失败和重复无进展交回现有重规划/退避机制。

## 玩家接口与后续阶段

提供只读检索、状态、命名/pin、失效、删除、暂停观察和人工确认连接等小接口；新事实层中模型只能检索，不能确认连接、强写置信度或删除玩家记忆；旧 `note` 仍作为未核验笔记兼容。玩家可用 `memory remember <kind> <type> [名字]` 明确报告机器人当前位置，始终标为玩家报告。原 `mark/go` 接口保留；新 `go` 的未知地点/错维度必须返回明确失败回执。

v1 不承诺跨维度自动赶路，不自动进入候选结构，不把所有路线称为安全，也不引入向量数据库或付费 embedding。后续可用经过验证的有向门户图做路线建议，再独立验收真实跨维度执行。

## 验证门槛

- 原有基线 341 项测试和语法检查已通过。
- 临时目录真实持久化/重启、世界/level 隔离、去重、删除不复生、人工保护、容量/TTL、损坏/未来版本与写盘失败。
- 观察器预算、未知块、结构候选、门户接触/死亡/管理员传送/同 level 折跃及 epoch 竞态。
- 真实 bot 入口与 Agent 工作流（外部模型替身）验证旧响应取消、检索注入边界、未核验不记成功、容器旧收尾隔离。
- 独立 26.1.2 服务器和全新世界做协议/块观察、重启保留、管理命令和维度切换对照。它与生产世界/配置/玩家资产隔离；受控放置结构特征不冒充自然生成结构或自然 AI 全链路验证。
